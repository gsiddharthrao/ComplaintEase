# ComplaintEase Enterprise — Troubleshooting & Diagnostic Guide

This guide documents common operational exceptions, error codes, and practical resolution procedures for developers and operators.

---

## 1. PostgreSQL & Application Error Code Catalog

The application translates database SQLSTATE exceptions to structured HTTP responses in [error-handler.ts](file:///d:/complaint_project/apps/api/src/middleware/error-handler.ts).

| Error Code | HTTP Status | Meaning | Typical Cause | Resolution |
|---|---|---|---|---|
| **`P0001`** | `400 Bad Request` | Invalid status transition | Attempting an invalid jump (e.g. `submitted -> resolved` or from terminal `closed`) | Review [STATE_MACHINE.md](file:///d:/complaint_project/docs/STATE_MACHINE.md) to ensure transition exists in `ALLOWED_TRANSITIONS`. |
| **`P0002`** / `PGRST116` | `404 Not Found` | Complaint not found or inaccessible | ID does not exist, or caller's RLS policy evaluated to 0 rows | Verify complaint ID exists and caller is authorized (creator, active specialist, or admin). |
| **`P0003`** | `409 Conflict` | Optimistic concurrency version mismatch | Two operators updated the ticket simultaneously, or caller submitted a stale `expected_version` | Refresh the complaint record in the UI and re-apply changes on the latest version. |
| **`P0004`** | `403 Forbidden` | Workflow role permission denied | Employee attempting unpermitted transition (e.g. reopening someone else's ticket) or target assignee is not an employee | Ensure target user has `role = 'employee'`. Employees can only transition tickets actively assigned to them or reopen their own resolved tickets. |
| **`P0005`** | `403 Forbidden` | Direct status update blocked | Executing raw `UPDATE complaints SET status = ...` outside `transition_complaint()` | Status updates must only execute via `transition_complaint()`. |
| **`P0006`** | `403 Forbidden` | Audit log immutability violation | Executing `UPDATE` or `DELETE` on `audit_logs` | Audit trail is strictly append-only. Modification is forbidden by database triggers. |
| **`42501`** | `403 Forbidden` | PostgreSQL RLS violation / privilege denied | Non-admin attempting to modify protected columns (`role`, `department_id`) in `profiles` | Sensitive profile columns can only be modified through authenticated administrative endpoints. |
| **`CANNOT_DEMOTE_SELF`** | `400 Bad Request` | Admin self-demotion prevention | Administrator attempting to demote their own account to `employee` | An administrator cannot demote their own account. Another administrator must make the change. |

## 2. Concurrency Conflict (`P0003` / HTTP 409)

### Symptom
A user receives:
```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "Version conflict. Another user updated this complaint. Please refresh and try again."
  }
}
```

### Explanation & Resolution
ComplaintEase enforces **Optimistic Concurrency Control (OCC)**:
1. When a client reads complaint version `N`, it must submit `expected_version: N` when transitioning or assigning.
2. If another user transitions the complaint first, the database version increments to `N + 1`.
3. The second request is rejected immediately with `P0003` to prevent silent lost updates.
4. **Resolution:** TanStack Query handles this by invalidating the query cache upon receiving HTTP 409, prompting the user to refresh and view the updated incident timeline.

## 3. Storage & Attachment Upload Errors

### Error: `INVALID_STORAGE_PATH` (HTTP 400)
- **Cause:** Storage path violates the strict path convention `<user_id>/<complaint_id>/<uuid>.<ext>` or contains directory traversal sequences (`..`).
- **Resolution:** Client must use the path generated by `POST /complaints/:id/attachments/upload-url`.

### Error: `METADATA_MISMATCH` (HTTP 400)
- **Cause:** The declared MIME type (e.g. `image/png`) does not match the file extension in `storage_path` (e.g. `.pdf`), or the reported file size differs significantly from the uploaded object.
- **Resolution:** Verify file extension and MIME type match the allowed MIME types table.

## 4. PNPM Installation Stalls (`confirmModulesPurge`)

### Symptom
Running `pnpm install --frozen-lockfile` in non-interactive terminals appears to hang indefinitely.

### Explanation & Resolution
If `node_modules` was structured under a different pnpm version or virtual store directory, pnpm prompts for interactive confirmation:
`? The modules directory at ... will be removed and reinstalled from scratch. Proceed? (Y/n)`
- **Fix:** In `.npmrc`, set `confirm-modules-purge=false`. This instructs pnpm to recreate `node_modules` automatically without hanging on interactive stdin prompts.
